# Internationalization - Meteo360

Meteo360 supports French and English using Transloco with the MessageFormat plugin. All user-facing text is centralized in typed translation files. Language preference is persisted in `localStorage` and applied at bootstrap.

## Dependencies

```json
{
  "@jsverse/transloco": "^8.3.0",
  "@jsverse/transloco-messageformat": "^8.3.0"
}
```

## Configuration Location

The core i18n configuration lives in:

```text
frontend/src/app/app.config.ts
```

Current loader pattern:

```typescript
@Injectable({ providedIn: 'root' })
export class TranslocoInlineLoader implements TranslocoLoader {
  getTranslation(lang: string): Observable<Translation> {
    return of(lang === 'en' ? enTranslations : frTranslations);
  }
}
```

Relevant provider excerpt from `app.config.ts`:

```typescript
import { LOCALE_ID } from '@angular/core';
import { environment } from '../environments/environment';

provideTransloco({
  config: {
    availableLangs: ['fr', 'en'],
    defaultLang: 'fr',
    reRenderOnLangChange: true,
    prodMode: environment.production,
  },
  loader: TranslocoInlineLoader,
}),
provideTranslocoMessageformat(),
{
  provide: LOCALE_ID,
  useFactory: (): string => {
    try {
      const raw = localStorage.getItem(LANG_STORAGE_KEY);
      return raw && JSON.parse(raw) === 'en' ? 'en-US' : 'fr-FR';
    } catch {
      return 'fr-FR';
    }
  }
}
```

`LOCALE_ID` is resolved from `localStorage` at bootstrap so that Angular's `DatePipe` and `DecimalPipe` use the correct locale on load. Switching language at runtime via the language switcher updates Transloco templates instantly; date and number pipe formatting reflects the new locale on the next page load.

## Language Switcher

The `LangSwitcherComponent` at `frontend/src/app/components/lang-switcher/` provides the runtime language toggle. It calls `TranslocoService.setActiveLang()` which triggers `reRenderOnLangChange` and re-renders all Transloco pipes instantly. `StorageService.setLang()` persists the choice.

`StorageService.getLang()` returns a typed `'fr' | 'en'` value with built-in normalization: unrecognized stored values fall back to `'fr'`.

## Translation Sources

Translation files live in:

```text
frontend/src/app/i18n/fr.ts   (French — default)
frontend/src/app/i18n/en.ts   (English)
```

The project does not use JSON translation assets. New keys must be added to both files simultaneously.

## Usage Rules

- all user-facing Angular text must use Transloco keys
- standalone components that render translated text must import `TranslocoModule`
- do not hardcode visible UI strings in templates or components
- keep translation keys grouped by domain rather than scattering ad hoc strings

Template example:

```html
{{ 'weather.loading_forecast' | transloco }}
```

## Testing

Tests should use the shared helper in:

```text
frontend/src/app/testing/transloco-testing.module.ts
```

Rules:

- import `getTranslocoTestingModule()` instead of rebuilding Transloco test config inline
- keep test expectations aligned with the current translation keys
- keep translation fixtures synchronized with `frontend/src/app/i18n/fr.ts`

## Adding A New Language

1. Create `frontend/src/app/i18n/{lang}.ts` with all keys from `fr.ts`
2. Add `{lang}` to `availableLangs` in `app.config.ts`
3. Update `TranslocoInlineLoader.getTranslation()` to return the new translations
4. Extend `StorageService.getLang()` return type and validation
5. Update the `LOCALE_ID` factory and register locale data via `registerLocaleData()`
6. Update this file
